Спецификация под концепцию из `03-forestproof-final.md`. Концепция, проблема, актуальность и методологические границы — там; здесь модель данных, требования, сценарии, расчёты и источники.

## 1. Модель данных

```
Проект (ForestClimateProject)
  id · название · полигон (GeoJSON) · площадь · регион
  режим: с проектом | территория без проекта
     │
     ├── Метаданные реестра  [0..1]
     │     номер проекта · компания · методология
     │     дата начала и окончания зачётного периода
     │     наличие единиц в обращении
     │
     ├── Заявленные показатели  [0..1]
     │     площадь леса · биомасса · объём эффекта · дата мониторинга
     │     источник: реестр | задано пользователем
     │
     ├── Наблюдения по годам  [0..n]
     │     год · площадь леса · биомасса · погрешность · валидность
     │
     ├── События нарушений  [0..n]
     │     год · площадь · тип · пожарные признаки · доверие · источник
     │
     └── Расчёты  [0..n]
           id расчёта · дата · версия методики · версия алгоритма
           хеш входных данных · даты снимков · параметры
           результаты всех блоков
```

**Два режима.** «С проектом» — есть заявленные показатели, работает блок сверки. «Территория» — заявлять нечего, блок сверки скрыт, показывается физический потенциал.

**Источники полей.** Наблюдения и события считаются из спутниковых данных. Метаданные и заявленные показатели импортируются из открытой части реестра «Контура» (выгрузка XLSX) либо задаются вручную. Полигон оцифровывается один раз при добавлении объекта.

## 2. Функциональные требования

Приоритеты: **M** — без этого решения нет, **S** — сильно улучшает, **C** — если останется время.

### Вход и навигация

| № | Требование | П |

| FR-01 | Приветственный экран при первом запуске; дальше открывается из шапки | M |
| FR-02 | Шесть разделов в постоянной навигации: обзор, проекты, территории, наблюдение, расчёты, методика | M |
| FR-03 | Кнопка добавления участка доступна из любого раздела | M |
| FR-04 | Работа без регистрации: одно рабочее пространство, состояние на сервере | M |

### Обзор

| № | Требование | П |
|---|---|---|
| FR-05 | Плитки состояния: проектов в реестре, единиц в обращении, участков с границами, ориентир цены | M |
| FR-06 | Что изменилось за 30 дней по отслеживаемым участкам | S |
| FR-07 | Список участков, требующих внимания | S |
| FR-08 | Быстрые входы: каталог, добавление участка, методика | S |

### Каталог проектов

| № | Требование | П |
|---|---|---|
| FR-09 | Список **всех** проектов из выгрузки реестра, а не только посчитанных | M |
| FR-10 | Статус данных у каждого: рассчитан · границы не загружены · в расчёте | M |
| FR-11 | Фильтры: регион, методология, вид эффекта, наличие границ | S |
| FR-12 | Действие «загрузить границу» в строке проекта без геометрии | M |
| FR-13 | Выбор 2–4 проектов чекбоксами и переход в сравнение | M |

**FR-09 принципиально.** В реестре 132 проекта, посчитаны единицы. Показывать только посчитанные — значит скрывать масштаб и вызывать вопрос о масштабируемости. Показываем все, у непосчитанных честно пишем причину: реестр не публикует геометрию.

### Сравнение

| № | Требование | П |
|---|---|---|
| FR-14 | Матрица: площадь, биомасса с погрешностью, потери за 10 лет, свежие нарушения, пожарная экспозиция, уязвимость, доверие, свежесть наблюдения, статус сверки, ₽/га | M |
| FR-15 | Сортировка по любому столбцу | S |
| FR-16 | Сводный рейтинговый балл не выводится ни в каком виде | M |
| FR-17 | Цветом кодируются только уровни; числа остаются нейтральными | M |

**FR-17 — следствие FR-16.** Таблица, раскрашенная целиком, читается как сводная оценка, даже если поля с оценкой в данных нет.

### Добавление участка

| № | Требование | П |
|---|---|---|
| FR-18 | Добавление границы участка файлом GeoJSON или Shapefile | M |
| FR-19 | Обводка полигона на карте и ввод координат вершин | C |
| FR-20 | Проверка геометрии: система координат, тип, самопересечения, площадь, спутниковое покрытие | M |
| FR-21 | Обязательное поле «источник границы»; выводится на экране расчёта | M |
| FR-22 | Привязка к проекту реестра либо режим территории без проекта | M |
| FR-23 | Прогресс расчёта по шагам; окно можно закрыть, расчёт продолжается | S |
| FR-24 | Итог с идентификатором расчёта и переходом в участок | M |

**FR-21 — не формальность.** Все числа считаются по этому контуру. Если граница обведена по лесничеству, а не взята из официального источника, это допущение обязаны назвать мы, а не обнаружить проверяющий.

### Измерение

| № | Требование | П |
|---|---|---|
| FR-25 | Лесопокрытая площадь по годам за 10 лет | M |
| FR-26 | Надземная биомасса в т/га вместе с погрешностью продукта | M |
| FR-27 | Эквивалент запаса CO₂ с явным показом коэффициентов | M |
| FR-28 | События нарушений по годам с площадью | M |
| FR-29 | Пожарные признаки через пересечение с данными о гарях | M |
| FR-30 | Классификация события: подтверждено пожаром · не связано с пожаром · стресс растительности · тип не определён | M |
| FR-31 | Физическая углеродная экспозиция затронутой области | S |
| FR-32 | Индексы NDVI, NDMI, NBR, dNBR и снимки до и после события | C |

**FR-30 важно:** отсутствие пожарных признаков не означает рубку. Тип остаётся неопределённым, пока нет дополнительных сведений.

### Качество данных

| № | Требование | П |
|---|---|---|
| FR-33 | Полнота данных: доступных периодов из общего числа, валидное покрытие, дата последнего наблюдения, пропущенные годы | M |
| FR-34 | Доверие к измерению по составляющим: оптическое покрытие, свежесть, неопределённость биомассы, подтверждение из вторых источников | M |
| FR-35 | При недостатке данных выводится «данных недостаточно» вместо результата | M |
| FR-36 | Единая числовая оценка доверия вида «83 %» не выводится | M |

### Уязвимость

| № | Требование | П |
|---|---|---|
| FR-37 | Относительная уязвимость территории: низкая · средняя · высокая | M |
| FR-38 | Основные драйверы уязвимости списком | S |
| FR-39 | Числовая вероятность вида «36,73 %» не выводится ни в каком виде | M |
| FR-40 | Оценка помечена как аналитический скрининг, а не официальный расчёт риска реверсии | M |

*До готовности модели FR-37 закрывается прозрачной эвристикой по истории пожаров и доле потерь.*

### Сверка с заявленным

| № | Требование | П |
|---|---|---|
| FR-41 | Импорт заявленных показателей из выгрузки открытой части реестра | M |
| FR-42 | Построчное сопоставление заявленного и независимых данных | M |
| FR-43 | Сверка ведётся на дату отчётности проекта, а не на текущую дату | M |
| FR-44 | Год использованного наблюдения показан в шапке блока | M |
| FR-45 | События после даты отчётности вынесены в отдельный блок и не влияют на статус | M |
| FR-46 | Площадь сравнивается только с одноимённой базой: территория с территорией, лесопокрытая с лесопокрытой | M |
| FR-47 | Заявленный эффект вида предотвращённых выбросов всегда помечается несопоставимым | M |
| FR-48 | Статус сверки: существенных расхождений не выявлено · требует проверки · данных недостаточно · напрямую не сопоставимы | M |
| FR-49 | Несопоставимая строка показывается приглушённой с указанием причины, а не скрывается | M |
| FR-50 | Формулировки «проект врёт» и «обнаружен гринвошинг» не используются | M |

**FR-43 и FR-45 — пара.** Проект отчитался в 2023 году, спутник мы считаем на 2026. Сравнение в лоб даст расхождение у всех проектов просто от прошедшего времени. А пожар 2026 года — не расхождение с отчётом 2023 года: отчёт физически не мог его содержать. Это устаревание, а не несоответствие, и на экране подписывается именно так.

### Инвестиционный сценарий

| № | Требование | П |
|---|---|---|
| FR-51 | Независимые физические показатели отдельным блоком, не редактируются | M |
| FR-52 | Сценарная выручка = ожидаемый объём × цена; выручка на гектар с указанием базы площади | M |
| FR-53 | Источник допущений подписан: заявлено проектом либо задано пользователем | M |
| FR-54 | Переключение сценария цены: пессимистичный, базовый, оптимистичный | M |
| FR-55 | Ручной дисконт сценария | M |
| FR-56 | Автоматический пересчёт дисконта из оценки уязвимости не выполняется | M |
| FR-57 | Полный NPV только при наличии CAPEX, OPEX, графика выпуска, срока и ставки; иначе «сценарная оценка» | M |
| FR-58 | Матрица чувствительности по цене и ставке | S |

**FR-56 — принципиальное ограничение.** Модельная уязвимость подаётся аналитику как основание для суждения, а не как множитель к деньгам: официальный процент резервирования устанавливает методология и реестр.

### Краткая справка от ИИ

| № | Требование | П |
|---|---|---|
| FR-59 | Краткая текстовая справка по участку и по разделу обзора | S |
| FR-60 | Генератор получает **только готовый объект расчёта** и не обращается к исходным данным | M |
| FR-61 | Генератор ничего не вычисляет: он пересказывает уже посчитанные значения | M |
| FR-62 | Справка сохраняется внутрь расчёта и воспроизводится по его идентификатору | M |
| FR-63 | Под справкой перечислены идентификаторы расчётов, на которые она опирается | M |
| FR-64 | На справку распространяются все запреты формулировок из FR-36, FR-39 и FR-50 | M |
| FR-65 | Пометка «сгенерировано» рядом с заголовком блока | M |

**Зачем ограничения.** Продукт продаётся аудируемостью: каждое число раскрывается до источника. Свободный текст, который выводит что-то сам, ломает эту конструкцию первым же вопросом «а это откуда». Поэтому справка — форма подачи посчитанного, а не отдельный источник суждений.

### Нефункциональные

| № | Требование |
|---|---|
| NFR-01 | Готовые расчёты по демо-участкам кешируются в БД: **демо обязано работать без интернета** |
| NFR-02 | Проект собирается и запускается на чистой машине по README |
| NFR-03 | Все коэффициенты и допущения задаются в конфигурации, не зашиты в код |
| NFR-04 | Тяжёлые выгрузки считаются заранее, интерфейс не ждёт Earth Engine в реальном времени |
| NFR-05 | Регистрации нет. Одно рабочее пространство, состояние на сервере; в браузере хранятся только факт показа приветственного экрана и выбранная вкладка |

**Про NFR-05.** Все входные данные открытые — реестр и спутниковые продукты. Разграничивать нечего, а форма входа на защите добавляет только риск. В продакшене это будет корпоративный вход, а не регистрация по почте, поэтому строить её сейчас — строить не то.

## 3. Пользовательские сценарии

### UC-1. Выбор проекта из нескольких

**Актор:** инвестиционный аналитик компании, рассматривающей финансирование одного из трёх проектов.

**Шаги.** Открывает экран сравнения → видит, что проект C выглядит экономически привлекательнее → замечает у него повышенные свежие нарушения, высокую пожарную экспозицию и статус сверки «требует проверки» → открывает проект → в истории нарушений находит событие 2026 года → открывает событие: 18,4 га, пожарные признаки обнаружены → смотрит блок сверки: заявлено «потерь нет» → возвращается к сравнению.

**Результат:** экономическая привлекательность проекта C пересматривается; для дальнейшего due diligence выбирается проект B.

### UC-2. Проверка продавца перед сделкой

**Актор:** корпоративный покупатель углеродных единиц.

**Шаги.** Открывает проект → система подтягивает заявленные показатели из импортированной выгрузки реестра и считает независимые данные за тот же зачётный период → получает построчное сопоставление → видит расхождение по площади, биомассе и неучтённое пожарное событие → статус «требует проверки» → выгружает JSON расчёта.

**Результат:** идёт к продавцу с конкретными вопросами по конкретным гектарам, а не с общим недоверием.

### UC-3. Оценка зелёного кредита

**Актор:** кредитный аналитик банка.

**Шаги.** Открывает проект заёмщика → смотрит уязвимость и историю нарушений → смотрит доверие к измерению и полноту данных → в инвестиционном сценарии выставляет дисконт 30% и повышенную ставку.

**Результат:** заключение о надёжности будущего потока и обоснование ставки.

### UC-4. Мониторинг после сделки

**Актор:** покупатель, уже владеющий единицами.

**Шаги.** Открывает проект → видит новое событие нарушения → смотрит физическую углеродную экспозицию затронутой области.

**Результат:** основание обратиться к резервному счёту. С 1 марта 2027 это станет регуляторной процедурой.

### UC-5. Скрининг территории без проекта

**Актор:** фонд, ищущий площадки под новый климатический проект.

**Шаги.** Добавляет полигон → получает биомассу, динамику покрова, историю нарушений, уязвимость → в сценарии задаёт ожидаемый эффект и цену сам.

**Результат:** оценка пригодности территории. Блок сверки не участвует: заявлять нечего.

## 5. Расчётные цепочки

### 5.1. Измерение и углеродный контекст

```
S(t)        площадь леса на год t, га         ← Dynamic World / Hansen
AGB         надземная биомасса, т/га          ← ESA CCI Biomass
agb_sd      погрешность биомассы, т/га        ← ESA CCI Biomass

C_AGB     = AGB × 0,47                        доля углерода, дефолт МГЭИК
CO2_stock = C_AGB × 44/12                     эквивалент запаса CO₂ из биомассы
Запас на участке = CO2_stock × S(t)
```

**Название результата:** эквивалент запаса CO₂, полученный из биомассы. **Это не количество углеродных единиц.**

### 5.2. Нарушения и физическая экспозиция

```
Событие нарушения: год · площадь A · пересечение с данными о гарях
Тип = подтверждено пожаром | не связано с пожаром | стресс растительности | не определён

Физическая углеродная экспозиция = CO2_stock × A
```

Оговорка на экране: скрининговая оценка физического запаса внутри затронутой области, не объём аннулированных единиц и не подтверждённый объём выбросов.

### 5.3. Сверка

```
расхождение = (заявлено − независимые данные) / заявлено × 100%

|расхождение| ≤ 10%   → существенных расхождений не выявлено
10% < расх. ≤ 20%     → требует проверки
расхождение > 20%     → требует проверки, приоритетно
нет валидных данных   → данных недостаточно
показатели разного смысла или периода → напрямую не сопоставимы
```

### 5.4. Инвестиционный сценарий

```
Q   ожидаемый годовой объём эффекта   ← заявлено проектом либо задано пользователем
P   цена углеродной единицы           ← сценарий: пессимистичный | базовый | оптимистичный
h   дисконт сценария                  ← задаёт аналитик вручную

Сценарная выручка      = Q × P × (1 − h)
Выручка на гектар      = Q × P × (1 − h) / S

При полных входных данных:
CF(t) = выручка(t) − OPEX(t)
NPV   = −CAPEX + Σ CF(t) / (1 + r)^t,   r = 15–20%
```

**Три запрета в этом блоке.** Q не выводится из биомассы. Дисконт h не рассчитывается автоматически из оценки уязвимости. При отсутствии CAPEX, OPEX, графика выпуска и срока выводится «сценарная оценка», а не NPV.

### 5.5. Ориентиры для сценариев цены

Средняя цена около 700 ₽ за единицу на август 2026; первый крупный аукцион 2022 года прошёл по 1 000 ₽. Пессимистичный, базовый и оптимистичный сценарии задаются вокруг этого ориентира со ссылкой на источник.

## 6. Модель уязвимости

**Название:** Disturbance Susceptibility, относительная уязвимость территории к будущим нарушениям. Не «вероятность пожара».

**Задача.** Бинарная классификация по ячейкам сетки 1×1 км: наблюдалось ли нарушение покрова в следующем временном окне T+1…T+5.

**Метки.** Hansen Global Forest Change, канал `lossyear` — год потери по пикселям, 2001–2025.

| Группа признаков | Состав |
|---|---|
| История нарушений | доля потерь за 5 и 10 лет, годы с последнего нарушения, `treecover2000`, доля потерь в соседних ячейках в радиусе 5–10 км |
| Пожарная история | выгоревшая площадь за 5 и 10 лет, годы с последнего пожара, число термоточек вокруг |
| Топливо и структура | биомасса, доля класса «деревья», доля открытых классов рядом |
| Водный стресс и климат | PDSI, дефицит давления пара, осадки, максимальная температура — средние и аномалии за вегетационный период |
| Рельеф | высота, уклон, экспозиция склона |
| Доступность | расстояние до дорог, до населённых пунктов, до крупных рек, плотность населения |
| Охранный статус | попадание в ООПТ |

**Пропускаем сознательно:** грозовую активность (главный источник возгораний в тайге, удобного открытого датасета по Сибири нет) и аренду лесных участков (нет открытых данных).

**Модель.** CatBoost. Метрики ROC-AUC и PR-AUC.

**Четыре обязательных требования:**

1. **Контроль временной утечки.** Все признаки строго по данным до года T. Один «подсматривающий» признак даст ROC-AUC 0,95 и бесполезную модель.
2. **Пространственный holdout.** Случайный сплит завысит метрику: соседние ячейки почти идентичны. Тест — отдельным географическим блоком.
3. **Стратифицированная выборка.** Нарушения редки, около 5% ячеек. Смотреть PR-AUC.
4. **Калибровка** до любой интерпретации выхода как вероятности.

**Сбор выборки.** Окно 200×300 км вокруг демо-проектов → сетка 1×1 км → панель по годам T = 2013, 2015, 2017, 2019 с признаками до T и метками в T+1…T+5 → `stratifiedSample` 5–10 тысяч точек → `Export.table.toDrive` в CSV. Экспорт асинхронный.

**Вывод в продукте:** категория (низкая / средняя / высокая) плюс перечень основных драйверов. Модель в P1, не является зависимостью демо.

## 8. Границы решения

**Считаем сами:** площадь покрова и динамику, биомассу с погрешностью, события нарушений и пожарные признаки, эквивалент запаса CO₂, физическую углеродную экспозицию, полноту и свежесть данных, расхождение с заявленным, относительную уязвимость.

**Не считаем:** дополнительность, официальную базовую линию, утечку, точное количество единиц к выпуску, количество аннулированных единиц, официальный процент резервирования, юридический факт реверсии, сертифицированный углеродный баланс.

**Не выводим:** «NDVI → CO₂», «биомасса → углеродные единицы», числовую вероятность пожара на пять лет, сводный инвестиционный балл, NPV из неполных входных данных.

**Чем не являемся:** аккредитованным верификатором, реестром, эмитентом единиц, заменой официальному MRV.

Обоснование каждого пункта — в разделе 9 концепции.

Приложение выросло с трёх экранов до шести разделов. При одном фулстеке и окне до 19.09 23:00 живым будет не всё, и это распределение лучше зафиксировать заранее, чем обнаружить на защите.

### Живое, на реальных данных

Приветственный экран, обзор, каталог проектов, сравнение, карточка участка, журнал расчётов, методика.

Каталог здесь почти бесплатный: данные на все 132 проекта уже в выгрузке. Методика и приветственный экран — статика. Журнал расчётов — список из таблицы, которая и так есть по NFR-01.

### Живое, но тонкое

Территории и мастер добавления участка. Приём GeoJSON и проверка геометрии — основная работа; обводка на карте и ввод координат уходят в C.

### Только макет

Наблюдение. Список и лента рисуются на реальных событиях из расчётов, но подписки, уведомления и фоновая перепроверка не делаются. На защите проговаривается как следующий шаг.

### Краткая справка от ИИ

Живая, если останется время на интеграцию; иначе — заранее подготовленный текст, собранный по тем же правилам из готового расчёта. Во втором случае на защите это называется прямо.

### Что не делаем совсем

Печатный отчёт, сравнение двух расчётов, time slider, карта расхождений, обводка полигона на карте, уведомления по почте.
