# Руководство по внесению изменений (Contributing)

Мы рады приветствовать вклад сообщества в развитие проекта **ForestProof (Космо-Красноярск / StackMinds)**! В этом документе описаны правила участия и стандарты разработки.

---

## Как предложить улучшение или сообщить об ошибке

1. **Создание Issue**:
   * Перед созданием новой задачи проверьте существующие Issues, чтобы избежать дублирования.
   * Опишите проблему или предложение: укажите контекст, шаги воспроизведения, ожидаемое и фактическое поведение.
2. **Обсуждение**:
   * Для крупных архитектурных изменений создайте предварительное Issue для согласования решения с мейнтейнерами.

---

## Правила работы с ветками и запросами на слияние (Merge Requests / Pull Requests)

1. Сделайте `fork` репозитория или создайте отдельную ветку от актуального состояния `master` (`main`):
   ```bash
   git checkout -b feature/название-фичи
   # или
   git checkout -b fix/описание-исправления
   ```
2. Делайте логически законченные атомарные коммиты с понятными сообщениями:
   * `feat: добавить экспорт отчётов в PDF`
   * `fix: исправить расчёт базовой линии для загруженных полигонов`
   * `docs: обновить руководство по запуску`
3. Перед отправкой убедитесь, что код компилируется и все проверки проходят успешно:
   ```bash
   # Проверка фронтенда:
   cd app
   npm run build

   # Проверка бэкенда:
   pytest
   ```
4. Откройте Merge Request в ветку `master`:
   * Приведите краткое описание сути изменений.
   * Укажите номер связанного Issue (при наличии).
   * Заполните чек-лист готовности к слиянию.

## Требования к коду

* **Frontend**: TypeScript, React, Vite. Строгая типизация (`strict: true`), отсутствие ошибок `tsc`.
* **Backend**: Python 3.11+, FastAPI, SQLAlchemy, Alembic. Следование стандартам PEP 8. Все новые миграции базы данных должны быть зафиксированы в `api/migrations/versions/`.
* **ML / Аналитика**: Воспроизводимость расчётов, отсутствие утечки признаков между периодами (leakage prevention).
* **Стиль**: Чистый, самодокументируемый код. Сохраняйте существующие комментарии и логику верификации.

---

## Процесс код-ревью

* Все входящие запросы рассматриваются командой в течение 24–48 часов.
* По запросу ревьюера внесите необходимые исправления в ту же ветку — MR обновится автоматически.
