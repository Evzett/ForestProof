# ForestProof

**Предпроектный экспресс-скрининг лесных климатических проектов по открытым спутниковым данным.**

Сервис берёт контур участка и пару лет, считает изменение запаса углерода в надземной древесной биомассе, переводит его в CO₂-эквивалент, оценивает неопределённость и показывает, сколько потенциальных единиц остаётся после вычетов — с раскрытием каждого числа до источника, версии продукта и параметра.

Задача — **до дорогостоящих полевых работ** ответить на три вопроса: показывает ли участок положительный расчётный эффект относительно базовой линии, устойчив ли этот эффект к неопределённости спутниковых данных, и есть ли смысл продолжать детальную проработку.

## Что сервис делает

* **Считает по своему контуру, а не только по готовому набору.** Контур задаётся четырьмя способами: файлом GeoJSON, обводкой по настоящей карте, списком координат, таблицей-ведомостью CSV. Если контур лежит вне подготовленных данных, биомасса и потери покрова читаются окном прямо из открытых продуктов по HTTP Range.
* **Показывает происхождение каждого числа.** Источник, версия продукта, дата получения, контрольная сумма. Расчёт выгружается в JSON целиком — чтобы его можно было перепроверить, не доверяя нашему интерфейсу.
* **Ищет подтверждение.** Снимки Sentinel-2 «до и после» по рамке контура и гари MODIS за период — не для расчёта, а чтобы увидеть место.
* **Ведёт журнал.** У каждого расчёта есть автор, время, версии методики и алгоритма и хеш входных данных: совпадающий хеш означает, что вход не менялся.

## Чего сервис не делает

* Не выпускает сертифицированные углеродные единицы. `Q` — **потенциальное** количество единиц по правилам кейса.
* Не устанавливает дополнительность проекта: базовая линия задана условиями кейса.
* Не заменяет формальную валидацию и верификацию.
* Не называет причину изменения покрова без подтверждения: потеря покрова по Hansen — это снижение покрова, а не установленная вырубка.

## Главное свойство

**Недоступные данные не превращаются в ноль.** Если продукт не покрывает часть контура или год отсутствует, сервис говорит об этом, а не подставляет нули в расчёт. «Недоступно» и «ноль» — разные ответы, и смешивать их значило бы занижать результат на ровном месте.

Из того же принципа следует и остальное: при `R ≤ 0` отношение `H/R` **не вычисляется вовсе** — делить на неположительное бессмысленно, и в выводе стоит причина, а не число.

## Результат исследования в одну строку

На четырёх официальных участках `Q = 0`, и это **результат расчётных фильтров, а не сбой**: из 60 перебранных пар лет 51 дала `R ≤ 0`, а в оставшихся девяти эффект тонет в неопределённости (`H/R ≥ 8,55`). Подробно — [`docs/13-executive-summary.md`](docs/13-executive-summary.md).

## 1. Структура

| Каталог | Что внутри |
|---|---|
| `app/` | Веб-интерфейс: React 19, TypeScript, Vite |
| `api/` | Сервис расчёта: FastAPI, SQLAlchemy, Alembic, PostgreSQL |
| `forestproof_core/` | Расчётное ядро: формулы кейса, экономика сценариев, сверка заявленных показателей |
| `tools/` | Извлечение данных из набора, скачивание растров, свой читатель GeoTIFF, модель устойчивости |
| `data/` | Набор кейса: растры по участкам, описания источников, методика, локальный кэш |
| `docs/` | Постановка, контракты данных, границы проекта, пользовательские сценарии |
| `tests/` | Тесты расчёта, ролей, валидации и граничных случаев |
| `examples/` | Примеры контуров для загрузки в мастер |

Формулы живут только в `forestproof_core/`. `api/` и `tools/` их вызывают, интерфейс не считает ничего — он показывает посчитанное. Поэтому число на экране, число в API и число в выгрузке совпадают по построению, а не по совпадению.

```
                     браузер
                        │
                        ▼
              ┌───────────────────┐
              │  nginx (app/)     │  статика фронта + проксирование
              └─────────┬─────────┘
                        │ /api/ и /data/
                        ▼
              ┌───────────────────┐
              │  FastAPI (api/)   │  роутеры, роли, журнал, фоновые задачи
              └────┬─────────┬────┘
                   │         │
      ┌────────────┘         └─────────────┐
      ▼                                     ▼
┌───────────────┐                  ┌──────────────────┐
│ PostgreSQL    │                  │ forestproof_core │  формулы кейса
│ журнал, люди, │                  │ tools/           │  чтение растров
│ контуры,      │                  └────────┬─────────┘
│ задачи        │                           │
└───────────────┘                           ▼
                                  ┌──────────────────────┐
                                  │ открытые источники   │
                                  │ CEDA, Google Storage │
                                  │ LP DAAC, Element 84  │
                                  └──────────────────────┘
```

Путь данных от контура до числа: **проверка запроса** (ровно один источник контура, период по возрастанию, геометрия без самопересечений, площадь ≤ 2000 га) → **постановка фоновой задачи** (состояние в базе, окно можно закрыть) → **данные** (вырезка в наборе → тайл в кэше → продукт в облаке окном по HTTP Range) → **базовая линия** (общая для участка набора, выведенная из истории 2015→2019 для чужого контура) → **расчёт ядром** → **подтверждение** (снимки и гари по рамке контура) → **запись в журнал** с автором и хешем входа.

Технологии: React 19 + TypeScript + Vite + MapLibre на фронте; FastAPI + SQLAlchemy 2.0 + Alembic + PostgreSQL 16 на бэкенде; свой читатель GeoTIFF вместо GDAL.

Подробно, с обоснованием решений, — [`docs/12-arhitektura.md`](docs/12-arhitektura.md).

## 2. Требования к окружению

* **Python 3.12+** — расчётное ядро и инструменты. Проверено на 3.13.
* **Node.js 20+** — веб-интерфейс.
* **Docker** — для API с базой. Без Docker нужен свой PostgreSQL 16.

Геобиблиотек (GDAL, rasterio) в зависимостях нет: растры читает собственный `tools/geotiff.py`. Это снимает самую частую причину, по которой проект не запускается на чужой машине.

### Установка

```bash
python -m venv .venv
```

Активация — `.venv\Scripts\activate` в Windows, `source .venv/bin/activate` в Linux и macOS. Дальше:

```bash
pip install -r requirements.txt
```

Для запуска тестов дополнительно:

```bash
pip install -r requirements-dev.txt
```

Интерфейс:

```bash
npm --prefix app install
```


Сборка и проверки:

```bash
npm --prefix app run build
```

```bash
npm --prefix app run lint
```

Из корня репозитория:

```bash
docker compose -f api/docker-compose.yml up --build
```

Контекст сборки — корень, а не `api/`: образ копирует `forestproof_core`, `tools` и `data`, иначе сервису нечем считать.

Проверка, что сервис поднялся:



### Порядок воспроизведения с нуля

Полный путь от пустой машины до работающего сервиса:

Открыть `http://localhost:5173`. Проверка, что всё сошлось:

```bash
curl http://localhost:8000/health && python -m pytest tests -q
```

### Роли и учётные записи

Просмотр открыт без входа. Вход нужен там, где начинается запись: загрузка своего контура, запуск расчёта, удаление. **Три назначаемые роли:**

| Роль | Что может |
|---|---|
| **инвестор** | просмотр, денежная оценка, отбор участков |
| **оператор** | плюс загрузка контуров, расчёты, публикация своих участков |
| **администратор** | плюс учётные записи, роли, обслуживание источников |

Четвёртое состояние — **наблюдатель** — это не роль, а вид сервиса для того, кто ещё не вошёл. Назначить его нельзя: «понизить до гостя» — действие, которого в сервисе не существует, для этого есть блокировка.

Регистрация открыта и выдаёт роль оператора. Роли выше назначает только администратор — поля роли в форме регистрации не существует вовсе.

Пароли демонстрационных учёток берутся из `FORESTPROOF_OPERATOR_PASSWORD`, `FORESTPROOF_INVESTOR_PASSWORD` и `FORESTPROOF_ADMIN_PASSWORD`; без них пароль генерируется и печатается один раз. Секрет подписи токенов — `AUTH_SECRET`; без него он генерируется на процесс, и каждая перезагрузка выбрасывает всех из сервиса. Всё это задаётся переменными окружения и в репозиторий не попадает; образец — `api/.env.example`.

Пароли хранятся только хешем bcrypt. Права проверяются на сервере: скрытая в интерфейсе кнопка ограничением доступа не является.

**Демонстрационный режим.** В разработке сервис открывается администратором без входа — на защите никто не должен искать логин. Выключается `FORESTPROOF_OPEN_ADMIN=0`. Кнопка «Выйти» работает и в нём: после выхода вы остаётесь наблюдателем, вернуться в режим показа — кнопка «демо-режим» в верхней панели.

Подробности по API, деплою и контракту полей — в [`api/README.md`](api/README.md).

### Тесты

```bash
python -m pytest tests -q
```

Фронт:

```bash
npm --prefix app run build && npm --prefix app run lint
```

## 4. Входы и выходы

### Вход

Полигон в **WGS 84 (EPSG:4326)**, порядок координат `[долгота, широта]` — как в GeoJSON, — и пара лет из диапазона **2019–2024**. Конечный год должен быть больше начального. Ограничение площади — 2000 га.

```json
{
  "geometry": {"type": "Polygon", "coordinates": [[[40.67, 59.43], [40.70, 59.43], [40.70, 59.47], [40.67, 59.47], [40.67, 59.43]]]},
  "year_start": 2019,
  "year_end": 2024
}
```

Вместо геометрии можно передать `aoi_id` участка набора — экран участка и произвольный контур идут одним путём.

Примеры запросов лежат в `data/sample_requests.geojson`.

### Выход

Объект расчёта: площадь контура по долям пересечения пикселей, ряд запасов по годам, изменение запаса, `E` в т CO₂-экв., полуширина интервала `H`, базовая линия `E_base`, `R`, доля вычета за неопределённость, резерв, число потенциальных единиц `Q` и причина, если единиц нет. Плюс аудит-поля: идентификатор расчёта, хеш входных данных, версии методики и алгоритма, версии источников.

```bash
curl -X POST http://localhost:8000/api/calc \
  -H "Content-Type: application/json" \
  -d '{"aoi_id":"RU_MORDOVIA_03","year_start":2019,"year_end":2024}'
```

Контур **не обязан лежать внутри участков набора**. Если он снаружи, биомасса и потери покрова читаются окном прямо из открытых продуктов по HTTP Range, а базовая линия выводится по формуле кейса из собственной истории контура 2015 → 2019 и помечается как выведенная нами. Первый расчёт нового места занимает около полуминуты: данные едут из CEDA.

Отказ — это тоже ответ: если пара лет недопустима или площадь превышает предел, приходит код ошибки и **причина текстом**, которую интерфейс показывает вместо результата.

Список участков набора: `GET /api/areas`.

## 5. Внешние источники и кэш

| Продукт | Версия | Роль | Откуда |
|---|---|---|---|
| ESA CCI Above-Ground Biomass | v7.0, 2015–2024 | биомасса и её погрешность `AGB_SD` | CEDA |
| Hansen Global Forest Change | v1.13, потери 2001–2025 | области и год потери покрова | Google Storage |
| MODIS Burned Area | коллекция 061 | признак горения и интервал дат | LP DAAC |
| Sentinel-2 L2A | сцены 2019–2024, маска SCL | визуальное подтверждение «до / после» | Element 84 Earth Search |

Лицензии, требуемая атрибуция и ограничения каждого продукта — в `data/sources.csv`.

Проверить доступность источников без скачивания:

```bash
python tools/fetch.py --bbox 32.8 54.7 43.4 59.6 --years 2019 2024 --cover --dry-run
```

Прогреть кэш на всю территорию набора:

```bash
python tools/fetch.py --bbox 32.8 54.7 43.4 59.6 --years 2019 2020 2021 2022 2023 2024 --cover
```

Кэш лежит в `data/cache/`. Рядом с каждым файлом сохраняется `.json` с происхождением: URL, версия продукта, дата получения, размер в байтах и контрольная сумма SHA-256. Каталог в `.gitignore` — тяжёлые растры в репозиторий не попадают.

Работа без сети:

```bash
python tools/fetch.py --bbox 32.91 56.59 32.974 56.63 --years 2019 2024 --offline
```

Вырезки по четырём участкам кейса (`data/RU_TVER_01`, `RU_VOLOGDA_02`, `RU_MORDOVIA_03`, `RU_MORDOVIA_04`) хранятся в репозитории, поэтому расчёт по кейсу воспроизводится **без обращения к сети вообще**. Шести добавленным участкам нужен прогретый кэш — см. раздел 6.

Языковая модель для краткой справки подключается ключом на стороне сервера (`api/.env`, образец — `api/.env.example`). Без ключа сервис работает штатно: справка собирается шаблоном по тем же посчитанным числам.

## 6. Повторение расчёта на сохранённых данных

В наборе десять участков: четыре из кейса и шесть добавленных нами для демонстрации. **Растры четырёх участков кейса лежат в репозитории**, поэтому расчёт по ним повторяется без сети:

```bash
python tools/extract_case_data.py --data data --out app/src/data/case-data.json --only RU_TVER_01 RU_VOLOGDA_02 RU_MORDOVIA_03 RU_MORDOVIA_04 --verify
```

Занимает несколько секунд. Скрипт детерминированный: он зависит только от файлов в `data/`, поэтому результат повторяется побайтово.

Шести добавленным участкам растры читаются окном из тайлов в кэше — они весят гигабайты и в Git не хранятся. Чтобы пересчитать **весь** набор, сначала прогрейте кэш (раздел 5), затем запустите без `--only`:

```bash
python tools/extract_case_data.py --data data --out app/src/data/case-data.json --verify
```

Без прогретого кэша эта команда остановится с указанием, какого тайла не хватает и чем его скачать.

### Ожидаемые числа

Четыре участка кейса, период 2019–2024, учитываемый пул — живая надземная древесная биомасса:

| Участок | Площадь, га | `E`, т CO₂-экв. | `H`, т CO₂-экв. | `R`, т CO₂-экв. | `Q` |
|---|---:|---:|---:|---:|---:|
| RU_TVER_01 | 1750,4839 | −6 484,8 | 240 546,2 | −4 546,9 | 0 |
| RU_VOLOGDA_02 | 1617,7139 | 24 604,2 | 114 359,7 | −21 520,8 | 0 |
| RU_MORDOVIA_03 | 1829,6118 | 126 073,6 | 71 194,6 | −42 852,9 | 0 |
| RU_MORDOVIA_04 | 1832,7592 | 72 154,8 | 24 086,0 | −73 649,6 | 0 |

`Q = 0` на всех четырёх участках, потому что `R ≤ 0`: результат не превышает базовую линию. Отношение `H/R` при этом **не вычисляется** — делить на неположительное `R` бессмысленно, и в выводе стоит причина, а не число.

Положительное `E` — потеря углерода из учитываемого пула, отрицательное — накопление. Знак задан переводом: `E = −ΔC × 44/12`.

## 7. Проверка корректности расчёта

Самая короткая демонстрация того, что расчёт повторяет замысел автора кейса: средние запасы 2015 и 2019 годов, посчитанные `tools/extract_case_data.py`, сверяются с `reference_mean_*_tc_ha` из `data/methodology/baseline.csv`. Если площадное взвешивание пикселей или перевод биомассы в углерод сделаны иначе, средние разойдутся уже в шестом знаке.

Флаг `--verify` печатает сверку и возвращает ненулевой код при расхождении.

```
RU_MORDOVIA_04  2019  посчитано 13.176397871  опорное 13.176397920  |Δ| 4.88e-08  ok
```

**Три участка из четырёх совпадают до шестого знака. Мордовия-03 совпадает до пятого**: расхождение 3,7·10⁻⁶ т C/га при значении 36,4 — это 10⁻⁷ в относительной величине, но формально шестой знак не сходится, и мы это не замалчиваем.

Что проверено о причине. Способ агрегирования сомнений не оставляет: взвешивание по доле пересечения пикселя с контуром даёт расхождение 10⁻⁷–10⁻⁶, тогда как среднее по всем пикселям внутри промахивается на 10⁻², а среднее по центрам пикселей — на 10⁻¹. Метод верный, остаток — численный.

Расхождение связано с краевыми пикселями. У Мордовии-03 самый контрастный край из четырёх участков: средний модуль отклонения краевого пикселя от среднего — 35,9 т C/га против 12,1 у Мордовии-04, у которой ровно столько же краевых пикселей (234) и наименьшее расхождение (2,6·10⁻⁷). Где поле на границе контура однородно, разница в долях пересечения ни на что не влияет; где оно контрастно — проявляется в шестом знаке.

Это остаётся открытым вопросом к автору кейса: точный порядок вычисления долей пересечения в опорных значениях нам неизвестен.

## 8. Методика, параметры и допущения

Полное изложение — [`docs/06-kejs-pereorientaciya.md`](docs/06-kejs-pereorientaciya.md). Границы того, что сервис заявляет и чего не заявляет, — [`docs/07-granicy-proekta.md`](docs/07-granicy-proekta.md).

Все параметры расчёта читаются из `data/methodology/parameters.csv` и в коде не дублируются:

| Параметр | Значение | Что это |
|---|---|---|
| `CF_AGB` | 0,47 т C / т сухого вещества | углеродная доля, МГЭИК 2006, том 4, таблица 4.3 |
| `CO2_per_C` | 44/12 | перевод углерода в CO₂-эквивалент |
| `UNC_allowance` | 0,10 | порог вычета за неопределённость |
| `UNC_stop_ratio` | 1,0 | при `H/R ≥ 1` единиц нет |
| `BUF` | 0,15 | резерв |
| `LK` | 0 | утечка, сценарное допущение |
| `k` | 1,645 | множитель интервала |
| `ρs`, `ρt` | 0,5 / 0,7 | корреляции ошибки в пространстве и во времени |
| цены | 500 / 1500 / 4000 ₽ | ценовые сценарии |

Главные допущения, которые нужно знать, читая результат:

* **Пиксель сетки CCI на этих широтах — около 0,54 га, а не гектар.** Площадь считается по долям пересечения, а не счётом пикселей.
* **Интервал неопределённости сценарный, а не эмпирически откалиброванный.** Он получен переносом `AGB_SD` при заданных `ρs`, `ρt`, `k`. Число единиц целиком определяется этими допущениями, поэтому рядом всегда показана чувствительность к ним.
* **Базовая линия задана условиями кейса** экстраполяцией исторической динамики 2015–2019 и не устанавливает дополнительность проекта.
* **Независимых наземных измерений углерода в наборе нет.** Сравнение спутниковых продуктов между собой не является наземной валидацией.
* **Причина изменения покрова указывается только при наличии подтверждения.** Потеря покрова по Hansen — это снижение покрова, а не установленная вырубка.
* **Стоимость считается как `V = Q × p`** и ничем не дисконтируется: множителей риска и скидок в формуле нет.
* **Единицы — «потенциальные», по условиям кейса.** Это не сертифицированные углеродные единицы.

## 9. Развёртывание

Разработческий `api/docker-compose.yml` для этого не годится: он монтирует исходники, держит `--reload` и открывает базу наружу. Для сервера есть отдельный [`docker-compose.production.yml`](docker-compose.production.yml) — три контейнера: nginx со статикой фронта, API и PostgreSQL. Порт наружу открывает только nginx.

### Развёрнутый экземпляр

> 💡 **Резюме и рекомендация**
>
> * **Открыть в браузере:** **http://45.150.36.28/** — начинать отсюда.
>   Внутренние разделы: http://45.150.36.28/app/areas — каталог участков.
> * **Запросы к API:** http://45.150.36.28/api/areas
> * **Только `http://`, без `s`.** TLS на сервере не настроен, порт 443 не
>   слушается: `https://45.150.36.28` не откроется вовсе. Это не ошибка
>   развёртывания, а отсутствие домена — сертификат выпускается на имя, а
>   не на IP-адрес.
>
> Бэкенд и расчётный движок работают полностью.

| | |
|---|---|
| **Адрес** | **http://45.150.36.28/** |
| Каталог участков | http://45.150.36.28/app/areas |
| API | http://45.150.36.28/api/areas |
| Проверка живости | http://45.150.36.28/healthz |
| Сервер | Debian 13, 1 ядро, 2 ГБ памяти, 50 ГБ диска, Москва |
| Каталог на сервере | `/opt/forestproof` |

Домена пока нет. Когда появится — вписать его в `CORS_ORIGINS`, заменить адреса здесь и выпустить сертификат: фронт и API живут на одном origin, и адрес, по которому открывают сервис, должен быть в списке разрешённых, иначе фронт получит отказ от собственного API.

### Если страница открылась пустой

Скорее всего браузер держит в кэше `index.html` от предыдущей сборки. Он ссылается на файлы скриптов по старым именам с хешем, а после пересборки имена другие. Обновление с игнорированием кэша — `Ctrl+Shift+R` (`Cmd+Shift+R` на macOS) — возвращает страницу.

Признак именно этой причины: в консоли браузера ошибка о типе MIME — сервер отдал HTML там, где ожидался модуль JavaScript.

### Первое развёртывание

```bash
# на сервере: Docker
curl -fsSL https://get.docker.com | sh

# с рабочей машины: код без node_modules, .git, кэшей и секретов
tar --exclude='.git' --exclude='node_modules' --exclude='.venv'     --exclude='app/dist' --exclude='api/data/cache' --exclude='api/data/contours'     --exclude='__pycache__' --exclude='.env' -czf forestproof.tar.gz .
scp forestproof.tar.gz root@45.150.36.28:/opt/
ssh root@45.150.36.28 'mkdir -p /opt/forestproof && cd /opt/forestproof && tar xzf /opt/forestproof.tar.gz'
```

Секреты генерируются на своей машине и кладутся в `/opt/forestproof/.env` — образец и пояснения к каждому полю в [`.env.production.example`](.env.production.example):

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

```bash
cd /opt/forestproof
chmod 600 .env
docker compose -f docker-compose.production.yml up -d --build
```

Миграции и учётные записи трёх ролей накатываются частью запуска — отдельных команд не нужно. Без `seed_users` в базе не было бы ни одного человека, и войти в развёрнутый сервис было бы физически нельзя.

Проверка:

```bash
curl http://45.150.36.28/healthz          # nginx
curl http://45.150.36.28/api/areas        # API сквозь прокси: 12 участков
docker compose -f docker-compose.production.yml ps
```

### Обновление

```bash
cd /opt/forestproof
docker compose -f docker-compose.production.yml up -d --build
```

`.env` и тома с базой при этом не трогаются.

### Память

Машина с одним ядром и двумя гигабайтами — в обрез: сборка фронта в контейнере без свопа падает по нехватке памяти. Своп ставится один раз:

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

По той же причине uvicorn запускается **одним** рабочим процессом: второй не ускоряет, а отнимает память у чтения растров, которое здесь и есть настоящая работа.

### Демонстрационный режим на публичном адресе

По умолчанию на проде сервис требует входа. Режим «администратор без входа» включается **только** строкой:

```
FORESTPROOF_OPEN_ADMIN=yes-i-know-this-is-public
```

Значение длинное намеренно: случайной единицей или словом `true` открыть панель администратора в интернете нельзя. Включённый режим означает, что администраторский доступ есть у любого, кто знает адрес, — это законное решение для показа, но оно должно быть принято осознанно.
